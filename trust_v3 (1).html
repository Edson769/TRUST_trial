TRUST

Transport Resilient Unified Sensor Technology
KNUST · TRECK
Client: FAI “ROSDORNII”
Prototype concept

TRUST is a software layer for vehicles and ITS units. It fuses GNSS with sensors the vehicle already has — wheel-speed odometry and the gyroscope — plus the digital road map. It checks every GNSS fix before trusting it, keeps positioning when GNSS is lost or lies, and tells the operator the moment it can’t be sure through a live confidence score.

Problem it answers: positioning goes “blind”, with no reliable feedback, when the GNSS signal is lost (blocked or jammed) or faked (spoofed).

Four states the operator sees

NORMALGNSS passes all checks and is trusted. Confidence ≈100%. PT priority: sent.
DEGRADEDSignal lost (tunnel, jamming). Running on wheels + gyro + map. Confidence falls as drift grows. PT priority: sent, flagged (held below 60%).
ALERTGNSS fails checks → spoofing suspected. GNSS is ignored; backup takes over. PT priority: held, dispatcher told.
RECOVERINGGNSS is back and consistent. Trusted again after 3 good fixes in a row. PT priority: held until then.

Confidence never drops below 40% while the vehicle’s own sensors work — they still carry real information.

Functional requirements (what it must do)

  • F1 Estimate position continuously from in-vehicle sensors and GNSS.
  • F2 Detect GNSS signal loss (blockage or jamming).
  • F3 Detect GNSS spoofing, treated separately from jamming.
  • F4 Keep positioning without GNSS (dead reckoning + map-matching).
  • F5 Tell the operator: state, confidence and reason — never fail silently.
  • F6 Re-validate GNSS before trusting it again.
  • F7 Log every state change with a timestamp for audit.

Technical requirements (measured live)

What is real, what is simulated

  • Real The fusion engine, the three checks, the state machine, the confidence score and every measurement on screen.
  • Real Phone mode uses the phone’s own GPS, compass and accelerometer.
  • Simulated Attacks: no radio signal is transmitted. Jamming makes the receiver report “no fix”; spoofing injects false positions.
  • Simulated Simulated drive sensor errors: odometry ±0.4%, gyro bias ≤0.03°/s, GNSS noise ≈2 m.
  • Simplified A production system would use a Kalman filter; this prototype uses a simplified complementary filter.

Readiness & next steps

TRL 3–4: proof of concept with real phone sensors and measured results — not yet integrated in a vehicle.

  • 1 · Replace the simplified filter with an Extended Kalman Filter.
  • 2 · Feed real wheel-speed and gyro data from a bus (CAN bus).
  • 3 · Use ROSDORNII’s digital road network for map-matching.
  • 4 · Hardware-in-the-loop tests with recorded jamming/spoofing.
  • 5 · Write the nine numbers into a ROSDORNII standard.

Event log

60-scenario test

Runs the same engine on the simulated drive, faster than real time: 25 jamming attacks (60 s each), 25 spoofing attacks (15 gradual drag at 2–5 m/s, 10 sudden jumps of 40–300 m) and 10 clean drives to count false alarms. Each run uses new random sensor errors and attack timing.

Value proposition

For road authorities and transport operators who rely on satellite positioning, TRUST is a software layer that keeps vehicle position trustworthy when GNSS is jammed or spoofed — using sensors already on the vehicle — and tells the operator the moment it can’t be sure. Unlike more satellites or new roadside infrastructure, it needs no new hardware and never fails silently.
